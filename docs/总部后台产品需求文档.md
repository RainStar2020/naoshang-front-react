## 1. 背景与目标

### 1.1 背景

小程序 `naoshang-partner` 已具备会员学习、甄选商城、联营工具、推广素材等 C 端能力，内容与商品配置依赖总部写入。React 总部后台 `naoshang-front-react` 已有 Mock 专用页（HQ-01～26）与真实模式 `LiveModule` 通用壳，但真实模式下商品、课程、素材等多为同一套列表+JSON 参数模板，**缺少按业务形态拆开的专用运营表单**，运营无法按贴吧式富文本、二维码框选、成本/售价盈利提示等真实工作流完成配置。

### 1.2 目标

1. 按业务域拆清菜单与路由，告别「一套 LiveModule 包打天下」。  
2. 优先落地运营高频的 **商品中心、学习课程 CMS、推广素材、合伙权益与等级名、用户编号编辑**（P0）。  
3. 明确总部写入 → API → 小程序可见的验收链路与金额等阻塞项。  
4. 与 partner 映射职责边界一致：后台供总部人员；不复制个人购买/提现/上传二维码工作台。

### 1.3 非目标（本期不做）

- 通用退货退款换货、排课考勤考试证书、复杂促销、BI 大盘。  
- 门店老板/代理/合伙人的「个人后台」。  
- 前端伪造支付、合成终图、自行推导结算结果。  
- 完整在线客服坐席工单（HQ-25 仅协议与反馈预留）。

## 3. 全局约定

### 3.1 角色与鉴权

- 仅总部人员登录后台；业务身份（合伙人/门店/健脑官等）**不能**单独作为进后台凭证（HQ-01）。  
- 写操作统一：权限校验、操作原因、二次确认、资源 `version`、幂等键、审计回执（与 AI_HANDOFF / admin API 一致）。  
- 内部角色细分（运营/财务/超管）仍待定；实现时预留权限码，但产品验收以「有总部会话 + 模块权限」为准。

### 3.2 草稿 / 发布

- 内容类（课程章节、商品详情、素材、公告、协议、权益文案）默认支持 **草稿 → 发布 → 下线**。  
- 未发布内容不得出现在小程序正式目录；停用分类下已发布商品不得出现在消费目录（与 README HQ-09 Mock 规则一致）。

### 3.3 幂等与强一致业务

- 下单、支付、划拨、发码、核销、合店拒审退款、提现打款等：**以前端提交 + 服务端回执为准**，禁止前端推导终态。  
- 未知结果须可按原幂等键查询，不得换键重放。

### 3.4 金额单位（待冻结 · 阻塞风险）

| 来源 | 现状 |
|---|---|
| partner API / Mock | 多处按**整数分**校验（如订单 `payableAmount`）；商品展示字段存在元/分混用 |
| admin API 文档 | 用户曾拍板总部侧统一「**元**」，`number`，保留两位小数 |
| React Live 模式 | README：金额直接用后端「元」，不做分转元 |
| React Mock 历史 | 类型/服务层多用分，页面展示转元 |

**本期产品写法（未冻结前）**：

1. **界面一律按「元」展示与录入**（两位小数；成本价、售价、盈利提示同口径）。  
2. **提交字段与 API 对齐策略待业务+后端拍板**（全部元 / 全部分 / 按字段表）；在契约未出逐字段单位表前，**禁止**「全部改成元」粗暴切真接口。  
3. 本文验收以「界面元 + 与小程序展示一致」为产品验收；联调阻塞项在第 8 节跟踪。  
4. `rateBps` 仍为万分比，与金额单位无关。

### 3.5 富文本约定

- 统一结构化内容（现有 `RichContent` / 块级节点），**禁止把未消毒 HTML 当可信内容直接入库渲染**。  
- 课程：允许 `paragraph` / `image` / `video`（及必要的标题等）交错。  
- 商品详情：仅 `paragraph` / `image`；插入视频控件应禁用或保存时拒绝。  
- 图文素材：同课程级交错能力，但末尾须有**唯一**二维码预留位（见 §5.3）。

### 3.6 与 LiveModule 的迁移策略

| 阶段 | 策略 |
|---|---|
| 现状 | 默认真实模式大量路由指向 `LiveModule.tsx` + `services/real/registry.ts`；Mock 模式仍走各 `pages/*.tsx` 专用页 |
| 目标 | P0 五个能力改为**专用页面**（可复用列表/筛选组件，但表单与预览必须专用） |
| 过渡 | 未拆出的模块可暂留 LiveModule；**侧栏一级/二级以 §4.3 为准替换现有混乱的 `adminNavGroups`**；避免再新增「万能 JSON 编辑」作为正式运营路径 |
| 禁止 | 用 LiveModule 的 JSON 参数框冒充「已完成商品/课程/素材运营表单」 |

## 4. 信息架构：菜单与模块划分

> **菜单真相源**：本章（§4）是总部后台侧栏 **一级 → 二级** 分类的唯一产品依据。实现时以本章替换现有 `adminNavGroups` 的混乱分组；路由可仍扁平注册，但侧栏归属、命名与拆分必须以本节为准，**不得**按 Mock/Live 技术实现方式分组。

### 4.1 问题陈述

1. **技术壳掩盖业务边界**：真实模式大量路由指向同一套 `LiveModule`，运营侧表现为「列表能开、表单不像业务」——商品/课程/素材缺少类型分流、富文本、框选二维码、盈利提示等专用交互。  
2. **现网一级分组混杂**：`src/auth/access.ts` 的 `adminNavGroups` 把课程塞进「账号与会员」、素材塞进「内容与运营」、名额塞进「发码与权益」、代理埋在「系统与支撑」，且「收益」仅作「资金结算」下的单页「收益结算与冲正」，**无法**按身份查看合伙人 / 门店 / 代理收益。  
3. **产品原则**：按**业务域**聚合一级菜单；二级对应可落地的管理页；一级数量控制在约 8～12 个；用户点名的「收益」结构必须保留。

### 4.2 设计原则

| 原则 | 说明 |
|---|---|
| 业务域聚合 | 一级 = 运营心智中的业务域（账号、学习、商品、素材、合伙、门店、收益…），禁止「Mock 页 / Live 壳」当分菜单 |
| 一级克制 | 建议约 **10～11** 个一级（可微调，不宜再堆到 15+） |
| 二级可落地 | 每个二级对应一个（或一组 Tab 明确的）管理页；P0 专用表单见 §4.5 |
| 收益独立 | **「收益」必须为独立一级**；其下至少含合伙人收益、门店收益、代理收益 |
| 编号对照 | 二级旁标注 partner 映射 **HQ-xx**；与 admin API 历史导航序号冲突时以 partner 映射 + 本文为准 |
| 不建个人后台 | 不提供合伙人/门店/代理「个人工作台」复制；收益页是总部**联查与监管**，不是 C 端收入页搬家 |

## 5. 各模块详述

### 5.1 商品中心（P0 · HQ-09）

#### 5.1.1 能力概述

总部维护一级分类、商品类型、SKU、上下架与详情内容；小程序甄选 Tab（`selection/index`、`product/detail`）消费发布结果。

#### 5.1.2 商品类型（与小程序对齐）

创建商品时**必须先选择履约/商品类型**（机器编码稳定，展示标题可改）：

| 编码 `fulfillmentType` | 含义（产品说明） | 备注 |
|---|---|---|
| `PHYSICAL` | 实物商品 | 涉及物流交付 |
| `ACTIVATION_CODE` | 激活码类商品 | 与发码系统关联，购买≠自动激活 |
| `OFFLINE_SERVICE` | 线下服务 | 默认可由所属门店交付 |
| `COLUMN_ACCESS` | 专栏访问权 | 与 HQ-07 专栏绑定；可复购 |

> 以上以 partner 映射 / README HQ-09 / 小程序商城模型为准。admin API 中另写的 `VIRTUAL` / `MEMBERSHIP` 等若未在小程序落地，**本期表单不提供**，避免运营选到无履约路径的类型。

**规则**：

- 已保存商品**不可直接更改** `fulfillmentType`（需下架作废后新建，或走受控迁移--本期不做迁移）。  
- 一级分类：稳定 ID 与展示标题分离；停用分类后其已发布商品退出消费目录。

#### 5.1.3 新建 / 编辑表单字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 分类 | 是 | 来自启用中的一级分类 |
| 商品类型 | 是 | 上表枚举，创建时锁定 |
| 标题 / 副标题 / 封面 | 标题、封面是 | - |
| 成本价 | 是 | 界面「元」；≥ 0，最多两位小数 |
| 售价 | 是 | 界面「元」；≥ 0，最多两位小数 |
| 盈利提示 | 只读 | **盈利 = 售价 - 成本价**，随输入实时刷新；售价 &lt; 成本价时警告（是否允许保存由业务拍板，默认**警告可保存**并记审计，或产品选择拦截--见待确认） |
| SKU | 至少一档可上架 | 规格名、库存（非负或无限）、各档售价策略按现契约 |
| 详情富文本 | 否（上架前建议有） | **仅文字 + 图片**；禁止视频块 |
| 交付默认策略 | 按类型 | 所属门店 / 总部等（HQ-10）；可改单记原因 |

金额提交与 API 单位见 §3.4。

#### 5.1.4 详情富文本交互（验收）

1. 可连续输入文字；插入图片后，光标可位于图片**之后**继续输入文字（贴吧式块编辑）。  
2. 工具栏**不出现**或禁用「插入视频」；粘贴/导入含视频节点时保存失败并提示。  
3. 预览与小程序详情阅读顺序一致（块顺序即展示顺序）。

#### 5.1.5 验收标准（商品）

- [ ] 按四类 `fulfillmentType` 各能创建草稿并发布。  
- [ ] 成本价、售价录入后盈利实时等于售价-成本价（元，两位小数展示）。  
- [ ] 详情无法保存含视频的内容。  
- [ ] 发布后小程序 catalog / 详情可见；下架后不可见。  
- [ ] 写操作含原因、版本、幂等、审计。

### 5.2 学习课程 CMS（P0 · HQ-04）

#### 5.2.1 能力概述

维护会员等级、学习等级归属、章节内容（图文/视频课）；小程序 `member/index`、`learning/level-detail|article|video` 消费。激活某一会员等级后，其包含的学习等级全部解锁（禁止按学习等级单独收费）。

#### 5.2.2 富文本（贴吧式 · 验收必测）

| 能力 | 要求 |
|---|---|
| 交错插入 | 文字、图片、视频可任意顺序混排 |
| 光标继续输入 | 插入图片或视频后，光标在媒体块后仍可输入文字 |
| 块操作 | 支持上移/下移/删除块（与现有 Demo 编辑器能力对齐） |
| 资源 | 图片/视频走上传三步（intent → 字节 → completion），仅 READY 可引用 |
| 白名单 | 节点类型白名单；禁止任意 script/iframe |

#### 5.2.3 其它规则

- 同学习等级内解锁状态一致。  
- 人工开通/撤销/补发在 HQ-03；本模块聚焦内容与等级结构。  
- `/course` 真实模式不得再用「仅权益列表 + JSON」代替章节编辑器。

#### 5.2.4 验收标准（课程 CMS）

- [ ] 新建章节：输入文字 → 插图 → 再输入 → 插视频 → 再输入，保存后回读顺序一致。  
- [ ] 发布后小程序对应 lesson 可读；草稿不可见。  
- [ ] 无权限账号不可发布。

### 5.3 推广素材（P0 · HQ-24）

对照小程序 `partner/materials`、`material-edit` 与 README HQ-24。

#### 5.3.1 共性规则

- 状态：`DRAFT` / `PUBLISHED` / `OFFLINE`。  
- **原图唯一二维码填充区**；用户只上传自己的码；**服务端合图**；后台与小程序均 **禁止前端伪终图**（不得用 canvas 本地合成冒充已渲染结果给业务下载）。  
- 视频：**互动 H5**，默认 **不烧录** 二维码进视频文件。  
- 发布校验：图片/图文无有效二维码区不可发布；视频不可配置「烧录区」。

#### 5.3.2 类型一：图片素材

| 步骤 | 说明 |
|---|---|
| 1 | 上传一张底图 |
| 2 | 在底图上框选 **正方形** 二维码填充区（归一化坐标 0-1，存 `qrRegion`） |
| 3 | 发布后，小程序用户上传二维码 → 调用渲染任务 → **服务端**将码填入该框并出图 |

**验收**：无框选不可发布；框必须为正方形（产品允许轻微像素容差则文档化，默认严格 1:1）；合图结果仅来自服务端任务状态。

#### 5.3.3 类型二：图文素材

| 步骤 | 说明 |
|---|---|
| 1 | 后台编辑图文富文本（文字+图片为主，规则与课程类似，是否允许视频待确认；默认允许图片+文字） |
| 2 | **末尾预留**用户上传二维码位（唯一） |
| 3 | 用户上传后服务端填充该位 |

**验收**：无末尾二维码位不可发布；预览可见占位；填充后终稿来自服务端。

#### 5.3.4 类型三：视频素材

| 角色 | 行为 |
|---|---|
| 后台 | 常备 **HTML 模板**：中间区域可上传/替换视频；页面**右侧固定「聊天框」按钮**；点开后区域用于展示小程序用户上传的二维码（非烧录进 MP4） |
| 小程序 | 预览视频模板 → 使用该模板 → 上传二维码 → 二维码出现在聊天框点开后的区域内 |

**验收**：后台可预览模板布局（视频区 + 右侧聊天按钮）；保存后 `videoDeliveryMode=INTERACTIVE_H5`；不提供「把二维码烧进视频」的发布选项；小程序专用 web-view 路由若未就绪，在后台标明 `h5RouteReady` 缺口，但不降低模板配置完成度要求。

#### 5.3.5 验收标准（素材总）

- [ ] 三类素材均可独立创建、草稿、发布、下线。  
- [ ] 任一路径无法在仅前端环境下生成「业务认可的合成终图」下载。  
- [ ] 与 partner 映射 HQ-24 表述一致。

### 5.4 合伙权益与等级名称（P0 · HQ-14）

#### 5.4.1 四档等级

系统内稳定等级编码建议与现网一致（示例：`VIP` / `ANGEL` / `BOARD` / `FOUNDER` 或小批～总批对应关系由后端冻结）。**展示名称全部可配置**，不得写死「秘籍」等历史文案。

| 建议默认展示名（可改） | 说明 |
|---|---|
| VIP | 对应批发体系入门档（小批） |
| 天使 | 中批 |
| 私董 | 大批（历史文档偶写「秘籍」，**仅作别名迁移参考，界面默认用「私董」且可改**） |
| 联创 | 总批 |

后台提供「等级名称配置」：四档各一展示名（非空、长度限制、敏感词按运营规范）；保存后小程序合伙相关页展示新名称（需 API 下发，前端不写死）。

#### 5.4.2 权益内容

- 按等级编辑权益摘要 + **RichContent** 正文（`save-benefits` 类能力，见 admin API partners mutate）。  
- 年度经营权益规则、晋升任务进度仍以 API 为准；总部可人工升级并留痕（映射 HQ-14）。

#### 5.4.3 验收标准

- [ ] 修改任一档展示名并发布/保存后，接口与小程序展示一致。  
- [ ] 四档权益正文可分别自定义并回读。  
- [ ] 文档与代码均不把「秘籍」当作唯一正式名。

### 5.5 用户编号编辑（P0 · HQ-02 增量）

#### 5.5.1 格式

用户对外编号形如 `LC0001`：

| 部分 | 规则 |
|---|---|
| 前缀 | **仅** `VIP` / `TS` / `SD` / `LC`，UI 为**下拉框**，不可自由输入其它前缀 |
| 序号 | **恰好 4 位数字**（`0000`-`9999`），可改 |

#### 5.5.2 交互与校验

- 编辑入口在用户详情；保存需原因 + 二次确认 + 版本 + 幂等。  
- 前端与服务端双校验：前缀枚举、后四位 `/^\d{4}$/`。  
- 全局唯一：冲突返回明确错误，不覆盖他人。  
- 不在此入口改密码明文回显、不改经营身份结构（换店等仍走原能力）。

#### 5.5.3 验收标准

- [ ] 下拉仅四项前缀；手动篡改请求非法前缀被拒。  
- [ ] 后三位、五位、非数字均无法保存。  
- [ ] 合法修改后列表/详情/小程序资料展示新编号（以 API 字段为准）。
